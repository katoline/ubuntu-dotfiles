# OpenCode に作業を任せる（Codex）

> **Codex 専用。** OpenCode 自身では使わない（入れ子起動になる）。Claude 用の `.claude/skills/opencode/SKILL.md` は Claude 専用のガードを含むため全体を読まず、共有ランナーだけを使う。

OpenCode をサブエージェント代わりに使う。目的は Codex のトークン節約なので、手順は軽く回す。Codex の全セッションで常時有効で、実装・調査・テストは明示的な呼出しがなくても委譲する（Codex のサブエージェントは独立レビューだけに使う。`~/.codex/AGENTS.md` の「モデル運用（Codex）」）。

共有ランナーは委譲時の OpenCode を必ず `delegated-worker` Agent（軽量 worker）で起動する。OpenCode 単体を普通に起動したとき（既定の `build`）とは別物。軽量委譲は新規セッションで始め、`--session` は同じ worker タスクの続きに限定する。

## 役割分担

- **Codex**：要件整理・計画・設計・タスク分解・指示・レビュー・最終判断
- **OpenCode（`delegated-worker`）**：それ以外（実装・テスト作成・調査・ドキュメント更新など）。設計判断は渡さない

## 委譲の範囲

- メインセッションで常時有効（サブエージェントとして起動されたら使わない）。オプションは無い（旧 `--session-wide` / `--once` は廃止。指定されても無視して通常どおり委譲する）。
- 委譲する：実装（規模を問わず、レビューで見つかった修正を含む）・複数ファイルにまたがる調査・テストの作成と実行・ドキュメント更新。
- Codex が行う：単なる質問への回答・要件整理・設計・レビュー・最終判断・1〜2ファイルの確認・自明な局所修正（数行）・git の書き込み（`$pr`）・worktree の作成と削除・委譲指示より短く済む記録。
- ユーザーがその作業について「Codex でやって」等と明示したときだけ、委譲せずメインで行う。
- ホームや全プロジェクトに効く状態ファイル・環境変数・フックは作らない（常時有効はこのスキルと `~/.codex/AGENTS.md` の指示で実現している）。

## モデル

既定は共有ランナーの `opencode/deepseek-v4.1-flash-free`。利用上限（レート制限・quota）のときだけ、ランナーが次の順に1回ずつ自動で切り替える：

1. `opencode/deepseek-v4.1-flash-free`
2. `opencode/glm-5.3-flash-free`
3. `opencode-go/deepseek-v4.1-flash`
4. `console-anthropic/claude-sonnet-5-5#medium`（OpenCode に登録した Anthropic API キー経由。従量課金）

最後まで上限なら非0で停止する。停止したら Codex が実装を肩代わりせず、ユーザーに状況を報告して判断を仰ぐ。認証・Privacy の地域拒否・権限拒否・通信・モデル不存在・context length・その他の失敗は切り替えず停止する。途中まで進んで上限になった場合は、得られた OpenCode セッションを続けて未完了分から再開する。ユーザーが `--model provider/model#variant` を明示した場合は、そのモデルだけで実行し自動切替しない。Codex 本体のモデル設定は変更しない。

## 手順

1. Codex が計画を立て、OpenCode 向けの自己完結した指示を書く（OpenCode は会話を知らない）。対象ファイル・方針・制約・完了条件・検証コマンドを含める。必要なスキルは Codex が自分で読み、委譲指示には関連する制約だけを含める。Codex の承認・sandbox・フックは OpenCode 内のツールに引き継がれないため、必要な制約（触れてよい範囲、削除・sudo・グローバルインストールの禁止など）も明記する。最後に添える：
   > 日本語で「変更ファイル／実行した検証と結果／未解決点」の形で簡潔に報告すること。git commit / push / PR 作成・削除・グローバルなインストールはしないこと。
2. `exec_command` で実行する。`yield_time_ms` を短めに指定し、返された `session_id` を `write_stdin` で完了まで待つ。60秒以上黙らない。Claude 専用の `run_in_background` などの引数は使わない。

   ```bash
   bash ~/.claude/skills/opencode/scripts/run.sh --dir /abs/path/to/project --title 'codex: 作業名' <<'EOF'
   ...指示...
   EOF
   ```

   独立した作業が複数あっても、同じ作業ツリーでは1本ずつ逐次実行する（並行すると同じファイルを取り合う）。
3. 要約（最終回答・拒否された権限・失敗したツール）を読み、Codex が `git diff` で変更をレビューし、OpenCode の報告にかかわらずプロジェクトの検証コマンドを自分で完了まで待って実行する。見つかった実装修正は `--session <ID>` で OpenCode へ再委譲する（Codex が直してよいのは数行の自明な修正だけ）。
4. ユーザーに報告する：使ったモデル（自動切替した場合は理由・順・最終モデルと各試行のログ）・変更ファイル・検証結果・未解決点（拒否された操作を含む）。

独立レビューは共通ルールの「サブエージェント」節に従い、挙動に関わる変更は完了前にカスタムエージェント `reviewer` へ差分と要件だけを渡す（ドキュメントのみ・数行の自明な修正は Codex のレビューで済ませる）。

## 注意

- `--auto` は付けない（ask 規則の rm・git commit・git push 等が自動承認される）。
- 作業用 worktree の作成・変更・削除と安全な cleanup は Codex（親）が行う。`delegated-worker` は `git worktree list` だけを使える。
- 独立タスクは新規セッションで始め、履歴が大きくなったら必要な制約・差分・未完了事項だけを新規セッションへ引き継ぐ。
- 拒否された操作は別の書き方やツールで迂回しない。必要なら理由を示し、ユーザーに手動実行を依頼する。
- OpenCode の実行中は、同じファイルを Codex が編集しない。
