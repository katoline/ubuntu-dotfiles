# Codex 固有の補足

設定は `~/.codex/config.toml`、フックは `~/.codex/hooks.json`（dotfiles の `codex/` の宣言を home-manager がマージした実ファイル。trust・信頼ハッシュはホーム側だけに残る）。Claude Code の `settings.json`・Hooks の書き方は Codex に当てはまらない。共通の事故防止判定・検証ゲート・完了チェックは `codex/hooks/harness.sh` が Codex のイベントへ接続している。

# モデル運用（Codex）

メインセッション向け（サブエージェントとして起動されたら本節と `$opencode` は使わず、与えられた指示を実行する）。委譲の原則は共通ルールの「サブエージェント」。Codex 本体のモデルと reasoning effort はユーザーが `config.toml` で決める（`--model` で変えない）。

- **Codex（メイン）**：要件整理・設計・分解・指示・レビュー・最終判断。1〜2ファイルの確認と自明な局所修正は自分で行ってよい
- **OpenCode**：実装・複数ファイルにまたがる調査・テスト作成と実行・ドキュメント更新は、ユーザーの明示的な呼出しがなくても `$opencode` スキル（`~/.codex/skills/opencode/SKILL.md`）で委譲する。Codex のサブエージェントへは回さない
- **Codex のサブエージェント**：独立レビューだけに使う。カスタムエージェント `reviewer`（読み取り専用・メインと同じモデル）に、差分と要件だけを渡す

運用：

- OpenCode の切替順（利用上限のときだけ）はランナーが自動で行うので、手で `--model` を指定しない
- 切替先まですべて上限になったとき、または OpenCode が使えないとき（認証・地域拒否・未インストール等）は、Codex のサブエージェントやメインで実装を肩代わりせず、状況を報告してユーザーに判断を仰ぐ
- ユーザーが「Codex でやって」等とその作業に明示したときだけ、OpenCode を使わずメインで行う
- OpenCode が報告した検証結果は鵜呑みにせず、変更後にプロジェクトの検証コマンドをメインが完了まで待って実行し直す（検証ゲートは OpenCode の編集を検出しない）

# フックの挙動（Codex）

- PreToolUse は拒否専用（承認を返せない）。既定ブランチへの commit・push、宛先を判定できない push、`--amend` / `--no-verify`、PR のマージ、force push、範囲外の削除・`sudo`、サブエージェントの git 書き込みを拒否する。それ以外の作業ブランチでの commit・push・PR の作成と更新は承認ポリシーに任せる
- 共通ガードが確認を求める操作も拒否される。対象のコマンドと理由を示してユーザーに手動実行を依頼する（PR のマージはユーザーが指示したときも Codex からは実行せずユーザーに任せる）。別の書き方やツールで迂回しない
- 検証ゲート：dotfiles の検証対象を編集したセッションでは、検証コマンドが成功するまでターンを終えさせない。長い検証は `write_stdin` で完了まで待ち、成功行が完了結果に含まれることを確かめる
- 完了チェック：ファイルを変更した（OpenCode への委譲を含む）ターンの終了時に、共通ルール「作業の進め方（PDCA）」の Check を促して続行させる（1ターン3回まで）。促されたら確認結果を報告に書き、未達があれば直してから終える
- 削除・移動の対象は絶対パスで書き、`workdir` 指定と相対パスを組み合わせない（フックに `workdir` が届かないため）
- フックの追加・変更後はユーザーが `/hooks` で確認し信頼する。エージェントは信頼状態を書き換えない

# スキルと `/pr`

- `/pr` 起動は文中の `$pr`、依頼の先頭語の `/pr`・旧 `/prompts:pr`。`~/.codex/skills/pr/SKILL.md` に従う（作業完了時の commit・push・PR も同じ手順）
- 他のスキル（`$readme`・`$nix-setup`・`$git-pull`・`$clean-branches`）は `.claude/skills/` の共通手順を読む。Claude 専用のモデル名・ツール権限は持ち込まない
